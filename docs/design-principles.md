# Design principles

Sauce Code is ordinary readable text with useful structure. Preserve source spelling, quantities, provenance and token spans. Parse syntax independently of canonical knowledge; unresolved words are not permission to invent meaning.

Sauce Code is the authored representation. Compact is generated prose, not a replacement source. Original Source is retained literally rather than reconstructed. Renderers must escape ordinary text, keep view controls independent and avoid presenting unknown information as established knowledge.

Local roles, shared identities and reference-page eligibility are distinct. Canonical links must not determine semantic colouring. Ingredient parts, preparation states, equipment subtypes and process context each express different relationships.

Precision belongs to the quantity expression: ! is accurate/measure closely, ~ approximate, ~~ very approximate. Future unit conversion must never imply more precision than the source. Scaling, locale and conversion must preserve uncertainty and authored intent.

Conversion stage describes maturity, not authorship or human review. Hidden/noindex site behavior is discoverability policy, not privacy: source may remain public. Automated quality scores are structural review hints, not culinary verdicts.

The canonical wordmark is `<Open> {Sauce} (Food)`, with `<Open>` #DA8E8E, `{Sauce}` #B8A4D5 and `(Food)` #B5E1B8. Light mode uses dark text centred in clean rectangular semantic-colour blocks; dark mode uses semantic-colour text without blocks. Both assets have transparent backgrounds.

Keep useful evidence and source attribution. Use normal forward changes and explicit fixtures; do not replace regression coverage with broad count relaxations. Website composition and production operations are consumers of the language/library rather than requirements for using it.
