# Direction

Improve the language and shared culinary knowledge through representative recipes and human review. Keep the core useful without a particular website or host.

Authoring locale and scoped ingredient names are implemented. Future reader-facing work includes global Reading settings for naming locale, units and °C/°F; editable serving sizes and discrete-ingredient scaling helpers; warnings when large scaling changes require method adaptation; reader-friendly conversion/rounding that retains source precision; and baker’s percentages. The evidence-gated measurement helper is not broad automatic recipe conversion.

Other planned work includes functional ingredient properties, a product/expression registry, wiki-style knowledge editing and a nutrition subsystem. Personal collections may distinguish private recipes from indexed ones, and indexed releases from working revisions. Recipe topic pages for shared titles, lineage/forks and conditional method branches tied to ingredient choices remain future work.

Continue strengthening evidence-backed ingredient/equipment/process relationships and contributor workflows. Human browsing categories are distinct from semantic type_of relationships. A lightweight, multi-valued browsing layer covers ingredients, processes and equipment, with domain-validated categories and public category indexes. Continued editorial review can refine assignments without changing identity or enrichment semantics.

The current package remains private and contains compiled code only. Distribution of knowledge data needs a separate decision. The locally extracted corpus and site currently use an explicit local source integration contract; publishing destinations and pinned release contracts can be decided later without changing core semantics.

Do not infer that a recipe or knowledge entry has been human-reviewed merely because it renders successfully or has passed structural tests.
